# {{name}}

NetSuite SuiteCloud project in TypeScript, created with [nsk](https://github.com/DiegoModesto/ns-cli).

## Layout

```
{{sourceDir}}/App/
  _EntryPoints/     scripts NetSuite runs (one file per script, with @NScriptType)
  lib/              pure helpers, no N/* modules: easy to test
  services/         code that uses N/* modules (search, record...)
test/
  App/              tests, mirroring {{sourceDir}}/App
  mocks/N/          stand-ins for the N/* modules, used by Vitest
{{outDir}}/   compiled AMD files (generated by "npm run build", do not edit)
```

`_EntryPoints/ue_customer_email.ts` is an example: replace it with your own scripts. Create new ones
with `npx nsk generate <template> <name> --dir App/_EntryPoints`, then run `npm run format`.

## Commands

- `npm run build`: type-checks and compiles to `{{outDir}}`
- `npm run watch`: compiles on save and uploads each changed file to the account
- `npm run upload -- <file>`: compiles and uploads one file
- `npm run deploy`: compiles and deploys the project (`suitecloud project:deploy`)
- `npm test`: runs the tests (Vitest)
- `npm run typecheck`: type-checks scripts and tests
- `npm run lint` / `npm run format`: checks / fixes lint and formatting (Biome)

Before the first upload or deploy, connect an account: `suitecloud account:setup` (or `npx nsk account setup`).

## Tests and N/* modules

NetSuite modules do not exist outside NetSuite, so `vitest.config.mjs` maps every `N/<module>` import to
`test/mocks/N/<module>.ts`. Control them in each test with `vi.mocked(search.create).mockReturnValue(...)`.
When a script uses a module that has no mock yet, add a file there exporting `vi.fn()` for the functions you use.
